## What changed for the owner in production

An opened date can now be **edited and cleared** from the Expiry page's Opened countdown section. Editing writes a new accepted `opened_date` assertion and supersedes the old one; clearing writes a null active assertion through the same `_write_assertion` path, so the old date stays in the superseded assertion and the audit trail is kept. A clear with no active date writes nothing. The served backend contains `POST /v1/plugins/expiry-tracker/assets/{id}/opened/clear` and `clear_opened_date`; the served JS bundle contains the clear path and the `Clear opened date` accessible label. **The live clear/edit was not exercised** — it would write the owner's own data; the first real clear awaits the owner's use. No provider call was made; spend $0; no database row was written by the serve.
