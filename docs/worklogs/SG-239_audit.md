### Below-95 investigation (`RATING_ISSUE.md`)

1. **Failure class:** prompt gap (packet), with a product gap underneath it — the app configures no logging.
2. **Root cause:** uvicorn's dictConfig sets no root level, so the app logger's effective level is WARNING and `logger.info` never reaches stdout. The SG-238 packet's acceptance was a `caplog` test, and `caplog` **forces** the level; nothing in that test, or in my audit of it, asked whether the record reaches the container log.
3. **Exact correction:** configure logging so the app's INFO records reach stdout — set the app logger (or root) to INFO at startup, or log through an already-configured logger such as `uvicorn.error` — and prove it **in a container** (the image's own probe), not only in `caplog`.
4. **Recurrence guard:** folded into the **next packet** — the roadmap row-11 slice carries the logging configuration (the audit rule: a fix found in an audit folds into the next slice's packet), and row 11's close-deploy rider is then the first place the pass line is observed in production. The second instance is added to Launcher #95.
